# Workflow Engine, Agent "Today" & Owner Dashboard (Spec)

Status: approved 2026-11-17 (decisions in §7). W1 in progress. Precedes Phase 1 in
`tenant-app-review-2026-11.md` and replaces its §6.1 / parts of §6.3.

> **Principle: the system runs the day, people execute it.** Every open lead
> always has exactly one next step with a due time. The system creates those
> steps, orders them, chases them, and escalates when they are missed. Agents
> never have to decide "who do I call now?"; owners never have to ask "is the
> team working?".

---

## 1. Why the current data cannot support this

What we store today answers *where is a lead* (stage, owner, source). It cannot
answer *what happened*, *what should happen next*, or *was it worth money*:

| Question an owner/agent asks | Missing today |
|---|---|
| What must I do now, and in what order? | No task / next-step concept at all (`Task` was removed in `9017031`). |
| Did the agent actually call? What happened? | `CALL_LOGGED` etc. exist in the enum but nothing writes them; no outcome, no duration. |
| How fast do we reach new leads? | Response time is inferred from "first activity" — an assignment by a manager counts as a response. No `firstContactedAt`. |
| How much did we sell? Commission? | No deal, price or commission — "Won" is only a stage. |
| Why do we lose? | Lost has no reason. |
| Where are deals stuck? | No `stageEnteredAt`; stage age is approximated from lead age. |
| Are we on target? | No targets. |
| Which source is worth its money? | No spend. |

Everything below adds the **smallest set of concrete records** that answers
those questions. No free-form "custom data", no opaque AI scores — each new
field is either filled by the system or forced at the moment the agent already
has the answer.

## 2. Data model additions

### 2.1 `Interaction` — what was done (new)

One row per real touch with a client. Replaces the unused `*_LOGGED` events as
the source of truth (a `LeadActivity` row is still written for the timeline).

| Field | Notes |
|---|---|
| `id, tenantId, leadId, userId` | `userId` = who did it. |
| `channel` | `CALL`, `WHATSAPP`, `MEETING` (office), `SITE_VISIT`, `VIDEO_CALL`, `EMAIL`, `SMS`. |
| `direction` | `OUTBOUND` / `INBOUND`. |
| `outcome` | Per channel, fixed list: `NO_ANSWER`, `BUSY`, `SWITCHED_OFF`, `WRONG_NUMBER`, `ANSWERED_INTERESTED`, `ANSWERED_NOT_NOW`, `CALLBACK_REQUESTED`, `NOT_INTERESTED`, `MEETING_BOOKED`, `VISIT_BOOKED`, `VISIT_DONE`, `OFFER_SENT`, `NEGOTIATING`, `RESERVED`. |
| `durationSeconds` | Optional (calls, meetings). |
| `note` | Optional short text. |
| `occurredAt` | Defaults to now; can be back-dated ≤ 48h. |
| `taskId` | The task this completed, if any. |
| `projectId` | Optional — what was discussed/visited. |

### 2.2 `Task` — what must be done next (new)

| Field | Notes |
|---|---|
| `id, tenantId, leadId?, assigneeId` | Lead-less tasks allowed (e.g. "Prepare weekly report"), but rare. |
| `type` | `CALL`, `WHATSAPP`, `MEETING`, `SITE_VISIT`, `SEND_OFFER`, `PAPERWORK`, `REVIEW` (manager tasks), `OTHER`. |
| `title` | Generated by the rule ("First call — new lead from Facebook Ads"). |
| `dueAt` | Exact time. `isAllDay` for "sometime tomorrow". |
| `priority` | `URGENT`, `HIGH`, `NORMAL`, `LOW` — set by the rule, boosted by lead heat. |
| `origin` | `SYSTEM`, `SELF`, `MANAGER`. |
| `ruleKey` | Which playbook rule created it (`first_contact`, `no_answer_retry`, …). |
| `status` | `OPEN`, `DONE`, `SKIPPED` (with reason), `CANCELLED` (system, e.g. lead closed). |
| `completedAt, completedInteractionId` | Closing a task = logging an interaction. |
| `escalatedAt` | Set when the miss was escalated to a manager. |

Partial unique index: one `OPEN` task per `(leadId, ruleKey)` so rules are
idempotent. "Overdue" is derived (`OPEN && dueAt < now`), never stored.

### 2.3 `Lead` — new fields (all system-maintained)

| Field | Filled by |
|---|---|
| `firstContactedAt` | First outbound `Interaction` by the assignee → honest speed-to-lead. |
| `lastContactedAt` (existing) | Now written only by real interactions (last touch). |
| `nextTaskDueAt` | Earliest open task → "leads with no next step" in one query. |
| `stageEnteredAt` | Every stage change → stage velocity, stuck deals. |
| `closedAt` | Won/Lost transition. |
| `contactAttempts` / `unansweredStreak` | Drives the no-answer cadence and "unreachable" suggestion. |
| `lostReasonId`, `lostNote` | **Required** when moving to a LOST stage. |
| `heat` | `HOT`, `WARM`, `COLD` — derived from the last outcome + interest level, shown everywhere, used for priority. Not a black-box score: the rule table is in §3.3. |

### 2.4 `LostReason` (new, tenant-configurable list)

Seeded defaults: Budget too low · Bought elsewhere · Postponed · Unreachable ·
Wants ready-to-move · Location · Payment plan · Fake / duplicate. Each reason
has `recyclable` + `recycleAfterDays` (e.g. Postponed → re-engage after 90 days).

### 2.5 `Deal` — minimal, created on Won (new)

Pulled forward from Phase 3 because **an owner dashboard without money is not
an owner dashboard.**

| Field | Notes |
|---|---|
| `leadId, projectId, agentId` | `agentId` defaults to the lead owner. |
| `unitType`, `unitCode?` | |
| `price`, `downPaymentPct?`, `paymentPlan?` (text for now) | |
| `commissionPct` → `commissionAmount` | Default % per developer/project later; manual now. |
| `status` | `RESERVED` → `CONTRACTED` → (`CANCELLED`). |
| `reservedAt, contractedAt, cancelledAt` | |

Moving a lead to WON opens a short "Deal details" step (project, unit type,
price; the rest optional). Cancelling a deal re-opens the lead.

### 2.6 `Target` (new)

`(tenantId, userId | null for team, period 'YYYY-MM', metric, value)` with
metrics: `DEALS`, `REVENUE`, `COMMISSION`, `INTERACTIONS`, `VISITS`. Managers
set them in Settings → Team; the system proposes defaults from the last 3 months.

### 2.7 `SourceSpend` (new, small)

`(tenantId, sourceId, period 'YYYY-MM', amount)` — entered monthly by the owner.
Enough for cost per lead / per visit / per deal without building campaigns yet.

### 2.8 `UserDailyStat` (new, computed)

One row per user per day, written by a nightly job (and refreshed for "today"
on demand): interactions by channel, tasks due / done / overdue, SLA hits and
misses, first-response minutes, visits, deals, revenue. Makes dashboards cheap
and gives streaks and personal bests for free.

### 2.9 `UserAchievement` (new)

`(userId, key, level, unlockedAt, value)` — written when a badge is earned so
we can show "unlocked on" and notify once.

### 2.10 Settings (TenantSettings / Settings → Leads & sales)

`workingDays`, `workingHours` (SLA clocks only run inside them),
`firstContactSlaMinutes` (default 15), `escalateAfterMinutes` (default 30),
`staleDaysByStage`,
`stuckDaysByStage`, `dailyInteractionGoal` (default 25),
`showLeaderboardToAgents`.

## 3. The playbook (how the system tells people what to do)

### 3.1 Engine

- **Event-driven**: lead created / assigned, interaction logged, stage changed,
  deal changed → evaluate rules for that lead synchronously (cheap).
- **Sweep**: BullMQ repeatable job every 5 min → time-based rules (SLA misses,
  stale, stuck, recycling, daily plan rollover).
- **Invariant check** in the sweep: every open, assigned lead has ≥ 1 open task;
  if not, rule R7 creates one. This is what makes "the system manages the user".
- All rules are idempotent via `(leadId, ruleKey)`; closing a lead cancels its
  open tasks.

### 3.2 Rules v1

| # | Trigger | Task created | Escalation |
|---|---|---|---|
| R1 | New lead assigned | **First call**, URGENT, due now + SLA (working hours) | Miss → notify manager (who can reassign). |
| R2 | Outcome NO_ANSWER / BUSY / SWITCHED_OFF | Retry: +2h → next day 11:00 → +2 days (+ WhatsApp template) | After 5 unanswered: suggest Lost "Unreachable". |
| R3 | CALLBACK_REQUESTED | Call at the time the agent picked | — |
| R4 | ANSWERED_* / OFFER_SENT / NEGOTIATING | **Next step is mandatory** in the log dialog; defaults proposed (offer → +2 days) | — |
| R5 | MEETING_BOOKED / VISIT_BOOKED | Confirm (WhatsApp) the day before + the meeting itself at its time | — |
| R6 | VISIT_DONE | Post-visit follow-up within 24h, HIGH | — |
| R7 | Open lead with no open task (sweep) | "Plan next step", HIGH | Counted against the agent ("leads without next step"). |
| R8 | No interaction for `staleDaysByStage` | "Revive" call, priority by heat | Listed for manager. |
| R9 | In stage longer than `stuckDaysByStage` | Manager `REVIEW` task "Stuck in Negotiation 21 days" | — |
| R10 | Deal RESERVED | PAPERWORK: collect documents, set contract date | Contract date passed → manager. |
| R11 | Deal CONTRACTED + 30 days | Check-in call + **ask for referral** | — |
| R12 | Lost with recyclable reason, after N days | "Re-engage" task to the original agent (or pool) | — |
| R13 | Unassigned lead | Manager task "Assign N new leads" (one rolling task per manager) | Unassigned > 30 min → notify all managers. |

### 3.3 Heat (visible, explainable)

HOT = last outcome in {visit booked/done, offer sent, negotiating, reserved} or
interest level HOT, within 14 days. WARM = answered & interested / callback
within 21 days. COLD = everything else or unanswered streak ≥ 3. Heat raises
task priority one level and orders the queue.

### 3.4 Daily plan

At the start of the working day the user's plan = open tasks due today +
overdue + a capped number of system suggestions (R8/R12) to reach
`dailyInteractionGoal`. The plan is frozen for scoring (so finishing early is
visible), new urgent tasks (R1) are appended live.

### 3.5 Assignment is the manager's job

The system never assigns leads by itself. It makes the manager's job fast and
visible instead:

- **Filters on the leads screen** (all combinable, saved in the URL):
  assignee (multi, incl. *Unassigned*), stage (multi), source (multi), project,
  heat, interest level, created date range, last contact (*never*, *> N days*),
  next step (*overdue*, *due today*, *none*), unanswered attempts ≥ N, lost
  reason, budget range.
- **Bulk actions on a selection or on *all leads matching the filters***:
  assign to a user, move stage (Lost asks for a reason).
- **Transfer**: move all open leads (optionally filtered) from one user to
  another — e.g. an agent leaves or goes on vacation. Their open tasks on those
  leads move with them; the activity log and audit record who moved what.
- Unassigned leads raise R13 and count in the "Needs attention" strip.

## 4. Agent — "Today" screen (default home for agents)

1. **Header** — greeting, date, **day progress ring** (done / planned), streak
   (consecutive working days ≥ 80% of plan), today's counters (calls · WhatsApp ·
   visits).
2. **Up next** — one large card: the single most important task, lead summary
   (heat, stage, project interest, last outcome), and **one-tap Call / WhatsApp**.
   Returning from the call opens the log dialog pre-filled.
3. **Queue** in strict order:
   - ⏱ *Speed to lead* — new leads with a live SLA countdown.
   - 🔴 *Overdue*.
   - 📅 *Scheduled* — meetings / visits with times (today + tomorrow morning).
   - *Follow-ups due today* — by priority then heat.
   - *Suggested* — revive / re-engage to reach the daily goal.
   Swipe/actions: Done (log), Snooze (requires reason, counted), Reassign request.
4. **Side panel** — month targets (deals, revenue, interactions) as progress
   bars with "on track / behind by N", upcoming in the next 3 days.
5. **Log interaction dialog** — channel → outcome (big buttons) → note →
   **next step** with smart defaults per outcome (§3.2) → optional stage
   suggestion ("Visit done — move to Proposal?") → Save. ≤ 4 taps for the common
   no-answer case.

### 4.1 "My performance" (achievements)

- **All-time totals** — deals, units, revenue sold, commission earned,
  interactions, visits, clients served.
- **This month vs target**, and month-by-month chart (deals + revenue).
- **Personal bests** — best month, fastest first contact streak, most visits in
  a week.
- **Badges** with levels (examples): First deal · 5/10/25/50 deals ·
  10M/50M/100M EGP sold · Speed demon (50 leads reached < 5 min) · Zero overdue
  week · 10-day streak · Referral magnet (3 deals from client referrals) ·
  Closer (win rate ≥ 25% over 20 leads).
- **Rank** in team (only if `showLeaderboardToAgents`).

## 5. Owner / manager dashboard v2

Organised by the five questions an owner actually asks; every number links to
the filtered list behind it.

1. **Needs attention now** (top strip, actionable) — SLA breaches today ·
   overdue tasks by agent · hot leads untouched > 48h · leads without next step ·
   stuck deals · unassigned leads. Each item has a one-click action (reassign,
   nudge agent, open list).
2. **Are we making money?** — Revenue & commission (contracted) vs target ·
   deals reserved / contracted / cancelled · **weighted pipeline forecast**
   (open leads × historical stage-to-won rate) · trend vs previous period.
3. **Is the team doing the work?** — team table: interactions today/week,
   task completion %, overdue, SLA compliance %, median first response,
   visits, deals, target %; activity heatmap (hour × weekday).
4. **Which leads are worth it?** — source table: leads, contact rate, visit
   rate, win rate, revenue, **cost per lead / per visit / per deal** (with
   spend); project demand (interest) vs sales.
5. **Where do we lose?** — stage-to-stage conversion (cohort by created month),
   average days per stage, **lost reasons** breakdown by source and agent,
   recycled leads won back.

Managers see the same, scoped to their team. The current KPI strip, funnel and
trend charts are kept but move under sections 2 and 5.

## 7. Decisions (approved 2026-11-17)

1. **Deal now** — yes, minimal (§2.5).
2. **Assignment** — manual by sales managers, with strong filters, bulk-by-filter
   and transfer (§3.5). No auto-assignment.
3. **SLA** — first contact within 15 min of working hours, escalate to the
   manager at 30 min; the manager decides whether to reassign.
4. **Leaderboard** — visible to agents: top 3 + own rank.
5. **Snoozing** — allowed with a reason; snoozes are counted per agent.
